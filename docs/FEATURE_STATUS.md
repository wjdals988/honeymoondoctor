# 구현 완료 · 미완료 기능 목록

[SPEC.md](SPEC.md) 7장(P0 기능 상세)과 6장(정보 구조)을 기준으로 실제 구현 상태를
있는 그대로 적는다. 구현하지 않은 기능을 구현한 것처럼 표현하지 않는다.

범례: ✅ 완료 · 🟡 부분 완료(핵심은 되지만 스펙 일부 미충족) · ⬜ 미구현

| 완료된 여행을 다른 계정에 공개 | ✅ | 완료된 여행만 공개 가능, 공개 시 초대코드 해시 자동 삭제(규칙으로 강제). 공개 사본은 원본과 분리된 `publicTrips` 컬렉션에 화이트리스트 필드(여행명·기간·도시명·일정 제목/시각/장소)만 발행 — 예약·경비·준비물·결정함·메모·예상경비는 제외. "전체 → 여행 둘러보기"에서 로그인한 다른 계정 사용자가 열람 가능. 데모 모드는 다른 계정 개념이 없어 "내가 공개한 여행"만 표시 |
| 동기화 상태·데모 모드 상태 표시 | ✅ | Phase 7, 전체 탭 "동기화 상태" |

## 도시(City) CRUD

스펙 4장은 "도시"도 CRUD 대상으로 명시하지만, 이번 구현에는 **도시 생성·수정·삭제
UI가 없다**. 시드로 들어온 4개 도시(프라하/토사 데 마르/바르셀로나/마드리드)는
조회만 가능하고, 일정·예산·장소 화면에서 선택지로만 쓰인다. 실사용상 이번
여행의 도시 구성이 이미 확정적이라 우선순위를 낮췄으나, 스펙 대비 명확한 미구현
항목이다.

## 요약

P0 기능의 대다수(인증·일정·예약·준비물·경비·예산·주변·오프라인·알림)는 스펙 그대로
구현되고 검증됐다. 명확히 남은 격차는 **여행 기본정보 수정/삭제, 도시 CRUD, 긴급상황
화면, 로그아웃** 네 가지이며, 전부 "이미 만든 기능이 잘못 동작"하는 문제가 아니라
"아직 화면 자체가 없는" 미구현이다. Firebase를 아직 연결하지 못해 실제 2인 동기화와
알림 실발사·재부팅 재예약은 코드 경로는 완성했지만 실측을 못한 상태다.
