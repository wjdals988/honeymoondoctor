# QA 체크리스트 & 수동 테스트 시나리오

이 문서는 [SPEC.md](SPEC.md) 12장의 필수 테스트 항목을 실제로 어떻게 검증했는지,
그리고 새 빌드가 나올 때마다 수동으로 다시 확인해야 할 시나리오를 정리한다.
자동화된 유닛/규칙 테스트는 매 Phase 종료 시 실행한 결과가 [PROGRESS.md](PROGRESS.md)에
누적 기록돼 있다. 여기서는 "실제로 손으로 눌러봐야 하는 것"에 집중한다.

## 실행 전제

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
```
- 데모 모드: `app/google-services.json` 없이 그대로 설치하면 자동 진입. 로그인 불필요.
- Firebase 모드: README의 "Firebase 연결 절차"를 마친 뒤 설치. Google 계정 2개 필요.
- 에뮬레이터: 이 프로젝트 전용 `HoneymoonDoctor_Dev` AVD만 사용(다른 AVD는 다른 세션이
  QA 자동화에 쓰는 공유 장비일 수 있음).

## 2. 매 릴리스 전 자동 검증 (5분)

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
cd firebase && npm test   # firestore.rules를 건드렸을 때만
```
- 유닛테스트 실패 0건, lint 차단 오류(Error) 0건을 확인한다(경고는 별도 관리 — 현재 7건,
  전부 경미한 스타일성 경고).

## 3. 탭별 수동 시나리오

### 3-1. 홈
- [ ] 여행 생성 직후: D-day, "다음 일정" 카드(시드 첫 항공편), 준비 현황 카드(미완료 필수
  준비물 8개, 확인 필요 예약 0건) 표시
- [ ] 일정 편집기에서 시간대가 다른 항공(예: 프라하 도착 시간대)을 넣고 홈에 "진행 중"→
  "다음 일정" 전환이 시간대 계산 오류 없이 되는지 확인
- [ ] 기기 설정에서 시간대를 변경한 뒤 앱으로 돌아와 다음 일정·D-day가 재계산되는지 확인
  (백그라운드 복귀 시 자동 갱신)
- [ ] 여행 기간 중 날짜로 기기 시간을 바꿔보고(`adb shell date`) "여행 중" 상태의 오프라인/
  동기화 배지가 나타나는지 확인(출발 전에는 표시 안 함이 정상)

### 3-2. 일정
- [ ] 같은 날짜에 시간이 겹치는 일정 2개 추가 → 두 카드 모두 "과로 경고" 배지 표시 확인
- [ ] 겹치는 일정 하나를 "완료"로 표시 → 다른 일정의 경고가 사라지는지 확인
- [ ] 연결된 예약이 있는 일정을 삭제 시도 → "연결된 예약 N건" 경고 문구 확인 후 삭제하면
    예약함에서 해당 예약의 연결 일정만 해제되고 예약 자체는 남아있는지 확인
- [ ] 일정 상세에서 Google Maps 길찾기 버튼 → 지도 앱(또는 브라우저 폴백) 실행 확인
- [ ] 종일 일정(숙소)과 시간 일정이 같은 날짜 섹션에 구분되어 표시되는지 확인

### 3-3. 주변
- [ ] 위치 권한 거절 상태로 진입 → "선택 도시 기준" 안내와 거리 미표시 확인
- [ ] 위치 권한 허용 후 Pull-to-Refresh → 거리 재계산·재정렬 확인
- [ ] 좌표 없는 장소 추가 → "위치 미확인" 섹션에 별도 표시(목록에서 사라지지 않음) 확인
- [ ] 카테고리 필터·미방문만 필터·정렬(추천순/거리순) 전환 확인
- [ ] 상위 3개 "지금 가기 좋은 처방"에 점수 근거 문자열(`거리+도시+우선순위+시간대+평점`)
    표시 확인
- [ ] `docs/templates`의 TSV에 임의 값을 채워 가져오기 → 미리보기에서 오류 행 사유·중복
    제외 건수 확인 → 유효 건만 가져오기
- [ ] 장소 목록을 TSV로 내보내기 → 파일 헤더가 템플릿과 동일한 열 순서인지 확인

### 3-4. 경비
- [ ] EUR/CZK로 지출 입력 시 환율 직접 입력 → KRW 환산 미리보기가 HALF_UP으로 즉시
    갱신되는지 확인
- [ ] 공동/개인 지출 구분에 따라 "1/2 정산 예상액"이 공동 지출 합계의 절반인지 확인
- [ ] 쇼핑 카테고리 지출을 "쇼핑 제외"/"쇼핑만" 필터로 분리 확인
- [ ] 예산 관리에서 도시×카테고리 예산 설정 → 경비 요약의 잔여/초과 표시 확인
- [ ] 예약의 예상 비용 합계가 실제 지출 합계와 별도로 표시되는지 확인

### 3-5. 전체 > 예약함 / 준비물 / 결정함
- [ ] 예약 목록에서 예약번호·PIN이 항상 마스킹돼 보이는지 확인(상세에서만 "보기"/"복사")
- [ ] 예약 상세에서 바우처 추가(PDF/JPG/PNG/WEBP) → 파일 목록에 표시, 외부 뷰어로 열기 확인
- [ ] 16MB 이상 파일 또는 허용 안 된 확장자 첨부 시도 → 거부 메시지 확인
- [ ] 예약 삭제 시 "바우처도 삭제할지" 별도 확인 다이얼로그가 뜨는지 확인(연결 일정 참조
    해제 확인 포함)
- [ ] 준비물 필수만 보기·담당자(공용/정민/찬희) 필터, 완료율 갱신 확인
- [ ] 결정함에서 후보 선택 → "결정 완료" 상태 전환, "결정 취소"로 되돌리기 확인

### 3-6. 전체 > 동기화 상태
- [ ] `adb shell svc wifi disable && adb shell svc data disable` 후 화면 재진입 →
    "오프라인" 실시간 표시 확인, `enable`로 복구 확인
- [ ] 알림 권한 거절 상태 → "거절됨" + 안내 문구 + "권한 요청"/"설정으로 이동" 버튼 확인
- [ ] 권한 허용 후 화면 재진입(ON_RESUME) → "허용됨" 갱신 확인
- [ ] (Firebase 모드에서만) 기기를 비행기 모드로 전환한 뒤 데이터 수정 → 온라인 복귀 시
    "마지막 동기화 시각"이 갱신되는지 확인

### 3-7. 인증 및 2인 공유 (Firebase 모드 전용)
- [ ] 소유자가 초대코드 생성 → 파트너 기기에서 코드 입력해 참여 요청
- [ ] 소유자가 참여 요청 승인 → 파트너 기기에 여행 데이터가 즉시 나타나는지 확인
- [ ] 3번째 계정으로 같은 초대코드 참여 시도 → Firestore Rules에 의해 거부 확인
- [ ] 승인 전 참여 요청자가 여행 데이터를 볼 수 없는지 확인
- [ ] 초대코드 재발급 후 이전 코드로 참여 시도 → 거부 확인

## 4. 검증 불가 항목과 사유

- **두 구성원 실시간 동기화(§3-7 전체)**: 이 개발 환경에 `google-services.json`이
  없어 Firebase 모드 자체를 실행할 수 없었다. Firestore Rules는 Emulator로 12개
  시나리오 전부 자동 검증했지만, 실제 Firestore 서버를 통한 2기기 간 실시간 반영은
  사용자가 README의 Firebase 연결 절차를 마친 뒤 직접 확인해야 한다.
- **WorkManager 알림 폴백 경로의 실제 발사**: 정확한 알람 권한이 없을 때 예약되는
  WorkManager 작업의 코드 경로는 존재하나(`ItineraryReminderScheduler.scheduleInexact`),
  실제 발사까지는 기다리지 못했다. `AlarmManager` 경로는 `dumpsys alarm`으로 정확한
  등록을 직접 확인했다(PROGRESS.md Phase 7 기록 참고).
- **재부팅 시 알림 재예약**: `BootCompletedReceiver`가 구현돼 있으나 에뮬레이터
  재부팅을 실행해 실측하지는 못했다.
- **바우처 실제 파일 첨부**: SAF 문서 피커를 통한 실제 첨부·검증 코드 경로는 있으나
  이 세션에서 손으로 첨부까지 마치지는 못했다(Phase 5 기록 참고).

## 5. 접근성 (TalkBack)

- 아이콘 버튼(수정/삭제/메뉴 등)에는 `contentDescription`을 부여했다(예:
  "${item.title} 삭제"처럼 대상을 특정하는 문구).
- 최소 터치 영역 48dp는 Material 3 기본 컴포넌트(IconButton, Card 등)를 그대로 써서
  충족한다.
- **미검증**: 실제 TalkBack을 켜고 각 화면을 순회하며 포커스 순서·읽기 순서를 확인하는
  전수 점검은 이번 세션에서 진행하지 못했다. 새 화면을 추가할 때마다 최소한 아이콘
  버튼의 `contentDescription` 존재 여부는 코드 리뷰로 계속 확인할 것.

## 6. 회귀 방지 팁

- 시드 데이터(항공 3건·예약 5건·준비물 8건·결정함 5건)는 여행 생성 시 1회만 삽입된다.
  데모 모드에서 반복 테스트할 때는 "데모 데이터 초기화"로 지우고 다시 여행을 생성해야
  시드 삽입 로직 자체도 매번 검증된다.
- 시간대 관련 버그는 대부분 "표시 시간대"와 "저장된 시간대"를 혼동할 때 생긴다.
  프라하→바르셀로나, 마드리드→인천처럼 출발·도착 시간대가 다른 항공 일정으로
  회귀 테스트하는 것이 가장 효과적이다.
